                    策略介绍
                    

                        
intro 展开一个蕴含或全称前提；蕴含引入要求条件演绎和逆演绎元定理，全称引入要求条件概括元定理。intros h1 h2 连续展开多个前提，rintro h1 ⟨ha,hb⟩ 可在引入后立即拆分一个合取/等价前提；省略名称时自动展开全部前导前提；exact h 用假设、定理或无前件规则完成目标；apply h 应用来源并生成前件目标。演绎元定理与逆演绎元定理解锁后，也可使用 apply >rule 或 apply <rule，但底层规则仍须在当前作用域可用；自动生成的子步骤也会检查其中的 >/< 前缀。

                        
assumption 自动使用与当前目标相同的局部假设；constructor 构造合取 A&B 或等价 A<>B；left/right 选择析取目标的一侧；symm 交换等式/等价两端；rfl 证明两端定义相同的等式。

                        
contradiction 使用同时存在的 P 与 ~P；by_contra h 加入反设 h:~P；by_cases h : P 建立 h:P 与 h:~P 两个分支；contrapose 把 A>B 改为 ~B>~A。

                        
have h : P 声明待证明事实，have h := f a b 实例化局部、页面命题或推理规则；规则带前件时会为 h 建立对应的证明子目标。apply f at h 用 h 作为 f 的首个参数并更新该局部事实，剩余前件会成为新的证明目标；specialize h a b 直接实例化局部的全称或蕴涵假设。依赖的内置规则未解锁时，系统只会使用当前作用域中结构等价的用户规则。

                        
cases h 或 rcases h 是 obtain 的 Lean 风格别名，可拆分合取、等价、存在或析取假设；也可写 cases h with ha hb 或 cases h with ⟨ha,hb⟩ 指定新假设名称。use x 用具体见证项证明存在量词目标 ∃y,P(y)，需要存在量词构造规则；obtain <x,hx> := h 可从存在量词假设中引入见证变量和对应命题；revert h 把命题假设重新放回蕴含目标。

                        
rw h/rw <-h 使用等式改写目标中的全部匹配项；rw [h,g] 依次改写；nth_rw 2 h 只改写指定的第几个匹配项。change P 或 show P 只接受与当前目标定义等价的命题。

                        
simp 使用局部和页面等式按缩短 AST 的方向反复化简；simpa using h 先化简再用假设 h 完成目标；simp [h] 加入指定等式，simp only [h,g] 只使用列出的等式。

                        
tauto 在完备性规则已解锁时自动证明纯命题目标；完成所有目标后使用 qed。

                        策略介绍
                        
    
                            
    intro 引入 Π/蕴含的前提；intros 连续引入，rintro ⟨ha,hb⟩ 引入后立即拆分合取或等价前提；exact 用证明项完成目标；apply 应用定理并为参数生成目标，apply f at h 则把局部假设 h 作为 f 的首个参数并更新其类型；specialize h a 实例化局部函数假设。
    
                            
    destruct 解构归纳类型、和类型或等式；Lean 风格的 cases/rcases 是同义入口，induction n with d dh 可为归纳步数据和归纳假设指定名称；ex、case、constructor、left/right 构造相应数据。
    
                            
    rw/rwb 改写，simpl/simp 化简，simpa using h 化简后使用局部证明，change P/show P 切换到定义等价的目标，rfl 证明定义相等，expand 展开定义；参数中的 _ 由系统尝试填充。
    
                            
    fnext 处理函数外延，eq 使用等式推荐，sup 构造 W 类型；所有目标完成后使用 qed。

                如何添加公理类型
                
    
                    
    在上方输入框写一行声明，使用 名称 : 类型 格式，例如 A : U。
    
                    
    要定义可展开的透明常量，使用 名称 := 项，也可以写 名称 := 项 : 类型。例如 inc := Lx:nat.succ x；定义会先通过类型检查，再桥接到创造模式的类型层。直接从公式或网页复制时，周围的不可见空白会自动规范化。
    
                    
    再添加依赖它的项或命题，例如 base : A、loop : base = base。声明按列表顺序校验，不能前向引用。
    
                    
    创造模式沙盒可以引用当前类型层已解锁的系统内置常量；名称区分大小写，例如 nat、ind_nat、succ。普通定理行和局部常量不会自动进入沙盒作用域，如需使用请在沙盒中显式声明。
    
                    
    普通归纳类型使用 inductive 声明，例如：inductive tri : U | nt : tri | 0t : tri | pt : tri。通过校验后会生成 tri、构造子和 ind_tri。
    
                    
    索引归纳把统一参数写在圆括号中，把索引写在方括号中。例如 inductive Vec (A : U) [n : nat] : U | vnil : Vec A 0 | vcons : Pn:nat,A -> Vec A n -> Vec A (succ n)。每个构造子必须显式给出返回索引；系统会生成保留索引约束的 ind_Vec 和 rec_Vec。
    
                    
    构造子的 iota 计算规则由系统自动生成：上例会让 ind_tri C cnt c0t cpt nt 计算为 cnt，对 0t、pt 也分别计算到对应分支。simpl、定义相等检查和 NbE 会自动使用这些规则。
    
                    
    当前版本不能在输入框中直接注册任意 pattern => result 计算规则。自定义计算规则必须先通过作用域、类型、严格正性、终止性和冲突检查；未经检查的规则会破坏定义相等，因此暂不接受。
    
                    
    沙盒声明是创造模式中的 trusted 公理；停用或删除后，依赖它的声明和类型层引用会一起失效。
