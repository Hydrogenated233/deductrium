# 类型论沙盒实施计划

## 目标

在游戏顶部增加独立的“沙盒”标签页，为创造模式提供自定义原始公理类型、普通归纳类型和高阶归纳类型（HIT）的实验环境。沙盒是创造模式的作者工作区；它拥有自己的声明、文件夹、顺序、验证状态和存档字段。

沙盒标签页的位置为：

```text
推理层 | 类型层 | 沙盒 | 进度层
```

沙盒必须与正常游戏环境隔离，但创造模式可以通过明确的可信桥接使用已经验证的沙盒声明。这里的“隔离”指数据所有权、存档字段、权限、生命周期和模式访问隔离；不指禁止创造模式消费一个受控的只读投影。桥接不得反向修改沙盒以外的全局定义、地图、成就或解锁状态。

### 术语与边界

- **沙盒工作区**：管理声明行和文件夹的独立工作区。排序、文件夹归属、折叠状态、展开文件夹才可拖入、文件夹底部插入、非编辑公式高亮和点击进入编辑，均复用类型层定理工作区的逻辑和 UI 契约，不另建一套列表语义。
- **沙盒声明**：由沙盒拥有的结构化类型、项、命题、归纳签名或 HIT 签名。声明保存稳定 ID、源文本、种类、依赖、文件夹归属、启用状态、验证状态和来源信息。
- **可信桥接**：从“已启用且已验证”的沙盒声明到创造模式类型层的一次性、单向投影。无体声明以 `trustedAxioms` 形式进入创造模式类型层；透明 `name := term` 声明以 `trustedDefinitions` 形式进入，并保留可展开的 beta/delta 行为。两者都标记为用户承担一致性责任的 `trusted` 来源，不伪装成系统证明，也不写入普通定理行。
- **模式边界**：沙盒只在创造模式实例化和显示。生存模式不创建沙盒 Worker、不读取桥接、不从沙盒存档恢复声明。
- **阶段边界**：阶段能力由编译器和内核检查决定，不能通过 UI 或语法别名越级开启。阶段 2 分为第一版和第二版；阶段 4 依次完成二维和三维，三维是用户可用功能上限。四维只保留实验 fixture、预检拒绝和资源边界。

## 基本原则

- 四个阶段严格按 `1 -> 2 -> 3 -> 4` 的顺序实施；阶段 2 的第二版和阶段 4 的二维里程碑必须先完成并通过验收，才能进入各自的后续扩展。
- 用户声明的原始公理必须显示为 `trusted`，不得伪装成系统已证明定理。
- 沙盒声明按存档隔离；可信桥接只向创造模式类型层增加 body-less 常量，不直接修改全局内置类型表或普通用户定义池。
- 所有声明都必须先完成语法、作用域和 Universe 检查，才能进入类型检查环境。
- 用户不得直接注册未经检查的任意定义相等规则。
- 计算规则必须经过模式、终止性和冲突检查。
- 沙盒生成器输出 `ruleSchemaVersion: 1` 的结构化证书；Core 从实际 family、构造子和消去器类型交叉验证证书，并重建每个点构造子的唯一 canonical iota 右侧。递归调用必须保持 universe、统一参数、motive、全部点/路径方法、子项索引和函数递归 telescope，不能用别名或其他捕获项替换。
- canonical 点计算规则发布前先检查 family、构造子和消去器类型；只有依赖这些点归约的 `apd_`/`ap_` 路径计算命题延后到规则发布后检查，避免候选规则参与验证自身核心类型。
- 沙盒验证放入独立 Worker 或进程，避免阻塞地图和普通证明助手。
- 存档格式必须带版本号，并允许后续迁移。

### 正式 HIT 维度边界

- 面向用户的正式 HIT 能力只覆盖一至三维；三维是产品功能上限，而不是当前实现暂时停留的版本号。
- 内部路径构造子统一保存在连续、canonical 的 `pathLevels` 中。当前有效层级固定为 1、2、3；该结构用于避免逐维扩展时重复改写存储格式，不代表已经实现任意维 lowering。
- 四维只允许作为 fixture、线性预检和声明数、源码字符、节点、步骤、超时资源限制的测试输入。`path4` 不进入正式 parser/lowerer、Core 注册、可信桥接或派生存档数据。
- 在具备通用 dependent transport、逐维端点语言和计算规则独立认证前，文档、UI 和发布说明都不得宣称任意维 HIT 支持。

### 计算规则的用户边界

当前版本没有把 `pattern => result` 作为沙盒输入语法。内核中的
`computeRules` 仅是归纳声明编译器和可信桥接使用的结构化接口；它不是
可由用户文本直接写入的后门。普通 `inductive` 声明会根据构造子自动生成
受检查的 iota 规则，并由 `simpl`、定义相等和 NbE 使用。将来若开放额外
规则，必须先完成作用域、类型、严格正性、终止性和重叠/冲突检查；无法证明
安全的规则只能作为普通命题保留，不能进入定义相等。

## 1. 自定义原始公理类型

### 目标

允许用户在沙盒中声明新的原始类型、普通常量和公理证明。

示例：

```text
A : U
base : A
loop : base = base
```

这些声明不要求提供定义体，因此属于受信任公理，而不是用户定义常量。沙盒也支持透明定义：

```text
inc := Lx:nat.succ x
id := Lx:A.x : A->A
```

透明定义会先经过同一套作用域、Universe 和 NbE 类型检查，再作为可展开的系统定义桥接到创造模式类型层。

### 实现内容

- 增加沙盒声明编辑器和声明列表。
- 支持类型常量、项常量和命题常量声明。
- 支持 `名称 := 项` 以及可选的 `名称 := 项 : 类型` 透明定义；定义只能依赖系统前置环境或列表中已经通过校验的沙盒声明。
- 通过类型层定理工作区适配器复用行、文件夹、排序、拖放和非编辑高亮渲染。
- 校验声明的类型本身是否合法。
- 校验 Universe 层级和绑定变量作用域。
- 检测名称冲突、循环引用和前向引用错误。
- 为每个公理显示明显的 `trusted` 标记。
- 建立独立于 `sysTypes` 和普通 `userDefs` 的沙盒源环境。
- 在创造模式建立显式可信桥接，将已启用且已验证的 body-less 声明同步到类型论 Worker；桥接不得成为生存模式或普通全局环境的隐式来源。
- 将沙盒声明和验证结果同步到需要它的类型论证明助手 Worker，但保持来源和 `trusted` 标记。
- 创造模式把当前类型层已解锁的系统规则作为只读 prelude 提供给沙盒；普通定理行和局部常量不隐式注入。
- 支持启用、停用、重排和删除声明；修改声明后只重验受影响的后缀。
- 支持导入和导出沙盒公理包。

### 验收标准

- 可以声明并使用一个全新的 `A : U`。
- 可以声明依赖 `A` 的点和函数常量。
- 未声明的自由变量仍然会被拒绝。
- 删除或修改公理后，依赖它的声明和证明会失效。
- 刷新页面或重新加载存档后，沙盒环境可以完整恢复。
- 生存模式不会加载或暴露沙盒公理。
- 创造模式只有在可信桥接启用时才能在类型层使用已验证声明；无体声明和透明定义分别以 trusted axiom/definition 进入，不变成普通定理行、地图对象、成就或解锁记录。
- 禁用、删除或重新排序声明后，桥接会按新的沙盒状态重建，不能继续消费旧声明。

## 2. 自定义普通归纳类型（第一版）

### 目标

支持有限构造子的严格正普通归纳类型，并自动生成构造、归纳和计算能力。

示例：

```text
inductive Nat2 : U
| zero2 : Nat2
| succ2 : Nat2 -> Nat2
```

### 实现内容

- 设计普通归纳类型声明 AST，不依赖字符串拼接生成核心项。
- 检查构造子返回类型是否为当前归纳类型。
- 检查递归出现是否严格正。
- 检查非索引参数和 Universe 层级；第一版不承诺索引归纳。
- 自动生成类型常量和构造子常量。
- 自动生成依赖归纳器和非依赖消去器（仅限非索引签名）。
- 为每个构造子生成受控的计算规则。
- 将自定义归纳类型元数据注册到 NbE 内核。
- 用类型元数据替换证明助手中固定的归纳类型白名单。
- 支持 `constructor`、`cases`、`destruct` 和 `induction`。
- 为构造子、归纳器和分支目标生成稳定名称。
- 将构造子和归纳策略加入证明助手推荐。

### 验收标准

- 可以定义、构造和使用 `Nat2` 一类普通归纳类型。
- `destruct n` 能生成正确的构造子分支。
- `induction n with d dh` 能为非索引数据生成数据参数和归纳假设。
- 构造子计算规则参与定义相等判断。
- 非严格正、返回类型错误或 Universe 不合法的声明会被拒绝。
- 修改构造子后，旧归纳器和相关缓存不会继续被使用。

### 阶段 2 第二版：索引归纳

索引归纳明确放在阶段 2 的第二版，不在第一版中通过特殊语法或固定类型白名单提前模拟。第二版在第一版的严格正性检查之上增加：

- 结构化保存参数、索引和构造子返回索引，不使用字符串拼接猜测索引关系。
- 检查构造子返回的索引是否在当前签名和作用域内，并拒绝不一致或越界索引。
- 生成保留索引约束的依赖消去器、归纳器和计算规则；递归出现必须仍然严格正。
- 在 `induction n with d dh` 等策略中生成与分支索引一致的数据参数和归纳假设。
- 将索引归纳元数据版本化；修改签名后使旧生成器、规则和缓存失效。

阶段 2 第二版验收通过后，才允许阶段 3 使用索引归纳能力。

## 3. 一阶路径 HIT

### 目标

支持包含点构造子和一阶路径构造子的高阶归纳类型。

示例：

```text
hit Circle2 : U
| base2 : Circle2
| loop2 : base2 = base2
```

阶段 2 的索引归纳完成后，一阶 HIT 也允许声明同一索引纤维内的路径。例如：

```text
hit FiberLoop [n : nat] : U
| baseF : Πn:nat,FiberLoop n
| stepF : Πn:nat,FiberLoop n→FiberLoop (succ n)
| loopF : Πn:nat,baseF n=baseF n
```

### 实现内容

- 在归纳类型签名中区分点构造子和路径构造子。
- 对路径构造子的两个端点分别进行类型检查。
- 检查路径端点只能引用当前可见参数和已声明构造子。
- 自动生成依赖消去器的路径一致性前提。
- 自动生成相应的 transport、`apd` 和非依赖 `ap` 规则。
- 明确区分点构造子的定义计算规则与路径构造子的命题计算规则。
- 禁止用户把任意路径规律直接注册为定义相等。
- 支持证明助手对自定义 HIT 使用 `cases`、`destruct` 和 `induction`。
- 支持 `rw`、`apd` 和路径计算定理使用新构造子。
- 对计算规则设置展开预算，避免路径归约造成无限展开。
- indexed hit1 复用普通索引归纳的 family、点构造子、递归子项索引和点 iota 骨架，但为每条路径独立推导所在纤维。左右端点必须形成同一 `H indices` 中的普通等式。
- indexed hit1 的依赖 coherence 使用纤维特化的 motive `λx:H indices,C indices x`；生成的 `apd_`/`ap_` 命题也必须先把消去器或递归器特化到该纤维，不能把仍等待索引参数的函数直接传给 `apd`/`ap`。
- Core 从 family、点构造子 `resultIndices`、路径端点和消去器 telescope 独立重建索引与 coherence，不信任 Sandbox 提供的派生索引或计算命题。
- indexed HIT 支持同纤维一阶路径、`path2` 的原子/组合/逆端点，以及同纤维 `path3` 的原子/组合/逆/受限 `refl path1` 二阶路径端点。`path2`/`path3` 的组合项必须逐项保持同一索引纤维，且中间边界由 Core 使用 NbE 定义相等认证；`refl` 只能引用当前 HIT 已声明的一阶路径构造子，任意二阶 AST 的反身项、跨索引 dependent path，以及函数型递归点参数出现在路径端点中的情形仍明确拒绝。

### 验收标准

- 可以声明一个类似 `S1` 的新 HIT。
- 点构造子和路径构造子可以在后续定理中使用。
- 归纳器会生成正确的点分支和路径一致性目标。
- `apd` 计算定理能够通过类型检查。
- `FiberLoop` 一类 indexed hit1 能保留点构造子的返回索引、递归子项索引和归纳假设，并生成可形成的 `ind_`、`rec_`、`apd_`、`ap_` 类型。
- 证明助手对 `x : FiberLoop n` 执行 `induction x` 时会生成与构造子结果索引一致的点分支和路径 coherence 分支。
- Core 会拒绝伪造的点结果索引、递归子项索引、路径纤维或 indexed coherence 类型；跨纤维路径和超出同纤维原子/组合/逆/受限 `refl path1` `path3` 范围的 indexed 高阶路径给出明确的不支持错误。
- 错误的路径端点、绑定变量或 Universe 层级会被拒绝。
- 路径规律不会未经检查地进入定义相等系统。

## 4. 高阶 HIT 与完整沙盒能力

### 目标

支持二维和三维路径构造子、路径之间的一致性条件及对应计算命题，同时完成完整的沙盒管理能力。二维是本阶段的首个强验收目标，三维是用户可用功能的合理上限。四维不进入正式 lowering 或可信桥接，只用于验证维度边界和资源限制。

### 实现内容

- 支持等式类型中的构造子继续作为高阶路径端点。
- **第一里程碑：二维**。支持二维路径声明、二维端点和二维 coherence，并生成相应的依赖消去器、`apd`、transport 和路径作用规则。
- 对二维规则做完整的维度、依赖、终止性、线性和重叠分析。
- **第二里程碑：三维**。在二维验收和资源边界稳定后，完成三阶端点、dependent coherence、`apd3`/`ap3` 命题计算规则和 Core 独立认证。
- 内部路径集合使用连续的 `pathLevels` 表示；`SandboxHitDeclaration` 只保存 0 维 `pointConstructors` 和 1–3 维 `pathLevels`，不再同时保存三组路径投影。该结构为以后逐维扩展保留接口，但不代表任意维已实现。1/2/3 维保持判别类型和各自的边界字段，不能用大量可选字段弱化 Core 认证。
- **四维实验边界**。允许 fixture 和预检器识别四维输入并报告声明位置、大小或预算错误，但 parser/lowerer/Core 必须明确拒绝，不能生成消去器或进入可信 bundle。
- 在具备通用 dependent transport 和逐维计算规则认证前，不宣称或暗示任意维完整支持。
- 对归纳签名进行维度和依赖关系分析，并把维度能力写入版本化元数据。
- 检查计算规则是否终止、线性且不存在危险重叠。
- 对无法证明安全的规则仅注册为命题定理，不注册为定义计算规则。
- 为复杂 HIT 增加独立的声明数、源码字符、节点、步骤和超时预算；当前不提供浏览器 heap 硬限制。
- 将耗时编译和验证任务放入沙盒专用 Worker 或独立进程。
- 支持取消、重启和恢复被中断的沙盒验证。
- 在存档中保存声明、信任标记、生成规则、版本信息和验证缓存。
- 提供沙盒包导入、导出、复制、禁用和清空功能。
- 对不同版本生成的沙盒包执行兼容性迁移或明确拒绝加载。

### 当前实现状态（2026-09-04）

- 一阶 HIT 已支持同纤维 indexed family：点构造子沿用结构化 `resultIndices` 和递归子项索引，路径 lowering 会把 motive、消去器和递归器特化到端点所在纤维。indexed `path2` 与 `path3` 的原子、组合和逆端点，以及仅引用当前一阶路径构造子的 `refl path1` `path3` 端点，已贯通 parser、lowerer、Core 独立认证、Worker/bridge 和证明助手分支；Core 会以 NbE 验证定义相等的索引、组合中间点边界及三阶路径共享的二阶边界。任意二阶 AST 的反身项、跨索引 dependent path 和函数型递归端点仍明确拒绝。
- 二维 HIT 已完成结构解析、消去器 lowering、命题计算规则和 Core schema 认证。
- 三维 `path3` 已支持原子二阶路径端点、使用 `▪` 的组合端点和 `inveq` 逆端点；统一参数、局部参数、递归组合边界和点边界都会被检查。三维是面向用户的最高维度，`path4` 及更高维仍明确拒绝。
- 三维端点已支持受限的反身形式 `refl loop`，包括同纤维 indexed HIT：它只能引用当前 HIT 已声明的一阶路径构造子，并由 Core 重新注入统一参数、检查局部 telescope 和重建二阶边界。它不是任意二阶路径 AST，也不会放开 `refl face` 或四维端点。
- 二维 `path2` 的一阶路径端点在非索引和同纤维 indexed HIT 中均支持构造子原子、`▪` 组合和 `inveq` 逆；lowerer 会递归生成 fiber-specialized dependent/recursor coherence，三维 `path3` 也可以安全引用同纤维二维构造子的复合与逆边界。
- 三维声明已生成真正的 dependent/recursor coherence binder 和点 iota 参数。HIT writer 使用 metadata v8：只传输连续的 `pathLevels`、结构化一阶路径表达式端点和结构化三阶表达式端点；Core 会把旧 v3-v7 metadata 一次性迁移为 v8，并重建验证一至三阶端点、统一参数及共享低维边界。
- 二维非依赖 action 现已额外生成兼容的新强计算槽 `ap2_<path2>`：它把二阶 action 与经两端 `ap_<path1>` 校正后的用户 `q2` 关联；旧 `ap_<path2>` 类型保持不变。
- 非依赖三阶 action 已生成 `ap3_<path3>`：它使用两端已认证的 `ap2_<path2>`、低维 `ap_<path1>` 和用户 `q3` 构造校正公式，并由 Core 独立重建类型。
- 依赖三阶 `apd3_<path3>` 命题计算规则已开放：生成式通过 `hit_map_transport` 构造随二阶路径变化的 dependent correction naturality，Core 会从 metadata 和消去器 telescope 独立重建公开/完整类型后再使用局部资源额度检查。
- 普通用户表达式仍使用全局 NbE 资源上限；只有已通过 Core canonical 重建的三维计算系统类型可以使用更高的调用级形成/输出额度。
- 浏览器沙盒现在默认启用声明数、源码字符、语法节点、验证步骤和时间预算；源码字符与 `path4` 位置在构造 AST 前线性预检，资源错误优先于后续 parser 诊断。
- 沙盒环境和 GUI 主存档共用 source-only 投影，只保存声明源码和工作区状态，不保存派生的 `hit`、`inductive`、`generatedNames` 或 `pathLevels`；Worker 每次从源码重新 lowering，validation cache 仅作为需经 Core 重认证的优化提示。
- GUI 的新增、编辑和存档恢复只建立 source-only draft，不在主线程运行 AST parser；普通声明的 `presentationAst` 与 HIT/归纳结构只由 Worker 回传并且不写入存档。
- 存档携带的 validation cache 仅进入下一次 Worker 请求，Worker 重认证前不会进入 autosave；声明、cache 与 DOM 只在新 bridge 成功发布后一起提交。
- GUI 与 Worker client 共用 ordered declaration validation key；只有源码、声明顺序、启停或递归停用变化才撤回 bridge 和 cache，空文件夹、折叠与重命名不会触发重复校验或使表达式检查误报存档变化。
- 三维 `path3` 组合/逆端点复用透明的路径复合/逆引理，并通过维度限定的 corrected coherence primitive 连接到 `ap3`/`apd3` 计算命题。Core 会逐参数重建和检查这些 primitive 的实例化类型；它们只属于三维可信基座，不构成四维或任意维计算规则。
- 一至三维 HIT 已允许严格正的直接递归点构造子。路径端点中的递归参数必须是可有限展开的点构造表达式，lowerer 会结构化生成对应归纳假设；函数型递归参数及路径局部参数递归引用 HIT 仍明确拒绝，避免在消去器 telescope 中引入未闭合的递归调用。

### 验收标准

- **二维验收**：可以声明并验证至少一个包含二维路径构造子的 HIT；高阶路径的端点和二维 coherence 条件能够正确显示和检查。
- **三维验收**：参数化和非参数化三维 HIT 都能生成并使用 dependent/recursor coherence、`apd3` 和 `ap3`；Core 能拒绝伪造的三阶边界或计算定理。
- **三维端点语言验收**：三阶端点至少覆盖二阶构造子原子、组合、逆，以及一阶路径构造子的受限反身二阶路径；每种形式的 dependent/action 计算证明都必须独立认证，不能由语法降级或 body-less 公理代替。
- **四维边界验收**：实验 fixture 能稳定触发 parser/lowerer/Core 的明确拒绝或资源错误；四维声明不能降级成三维成功，也不能进入存档桥接。
- 非终止、冲突或不合法的计算规则无法注册。
- 大型沙盒声明不会阻塞游戏主线程。
- Worker 重启后可以从存档重建相同的沙盒环境。
- 沙盒数据不会污染地图、成就、解锁状态或普通定理列表；创造模式的可信桥接只提供类型层检查所需的只读常量。

## 跨阶段基础设施

### 数据模型

建议使用结构化声明，而不是把声明仅保存为文本：

```ts
type SandboxDeclaration =
    | SandboxAxiomDeclaration
    | SandboxInductiveDeclaration
    | SandboxHitDeclaration;
```

每条声明至少保存：

- 稳定 ID
- 用户显示名称
- 声明种类
- Universe 参数
- 普通参数和索引
- 构造子和路径构造子
- 信任级别
- 编译结果版本
- 验证状态和错误信息
- 依赖声明 ID
- 文件夹 ID、统一显示顺序和折叠/停用状态（由共享工作区适配器管理）
- 可信桥接来源、目标模式和生成器版本（不得把桥接结果当作普通定义缓存）

### 内核边界

- 沙盒公理只扩展沙盒环境；在创造模式中，可信桥接可将已验证的 body-less 公理以受信任常量类型加入类型层，但不得写入普通用户定义表。
- 普通定义进入可展开定义环境。
- 归纳计算规则只能由受检查的声明编译器生成。
- 路径计算默认生成命题等式，不自动进入定义相等。
- NbE 只接收已验证、结构化和版本化的规则。

### Worker 与性能

- 沙盒配置作为独立消息传给 Worker。
- 按声明顺序增量追加，不为每条声明重复复制整个前缀。
- 修改声明时截断并重验依赖后缀。
- 缓存只保留从声明类型和编译结果可达的数据。
- 存档中的验证缓存使用版本化语义 epoch、完整 prelude 指纹和链式声明前缀指纹。缓存命中后仍逐条经过 Core 边界：公理重验类型形成，透明定义验证源项、缓存项和缓存类型一致，归纳类型/HIT 从源重新 lower 并调用 `registerSystemInductive()`。存档中的 `status: valid`、序列化 bundle、计算规则和 bridge 均不作为可信结果。
- 缓存格式、前缀、prelude、大小、深度或 Core 复核任一失败时，丢弃整段缓存并从源正常重验；缓存失败不能使存档加载失败，也不能留下部分桥接。
- 所有资源超限必须返回明确错误，不得退化为成功或空引用异常。

### 存档隔离

- 沙盒内容使用独立存档字段和版本号。
- 普通存档在没有沙盒字段时保持兼容。
- 生存模式加载时忽略或禁用沙盒环境，不恢复桥接。
- 创造模式加载后从沙盒存档重建可信桥接；桥接失败必须保留沙盒源数据并显示错误，不得静默写入普通环境。
- 沙盒导出包不得自动修改游戏进度和系统解锁内容。

## 测试计划

- 为每类声明增加最小正确性回归测试。
- 测试错误 Universe、自由变量、重复名称和非法依赖。
- 测试严格正性和非严格正性声明。
- 分别测试阶段 2 第一版的非索引归纳和第二版的索引归纳、索引保持及生成器失效。
- 测试构造子计算规则和定义相等。
- 测试一阶及高阶路径端点检查。
- 测试 same-fiber indexed hit1/path2/path3 的端点索引、递归点 iota、`apd_`/`ap_`/`ap2_`/`apd3_`/`ap3_` 形成、证明助手归纳、Worker 重建，以及合法受限 `refl path1`、伪造组合中间边界、跨纤维、错误 `refl` 引用和超出原子/组合/逆/受限 `refl path1` `path3` slice 的 indexed 高阶路径拒绝。
- 先测试二维 HIT 和二维 coherence，再测试三维 dependent/action 计算；四维只测试明确拒绝、资源上限和 fixture 形状。
- 测试 Worker 配置、取消、重启和顺序一致性。
- 测试存档往返和旧版本迁移。
- 测试沙盒与生存模式之间的隔离，以及创造模式可信桥接的启用、撤回和重建。
- 测试沙盒文件夹与类型层定理工作区的排序、折叠、拖入和非编辑高亮契约一致。
- 将大型 HIT 的时间和内存测试放入 `tests/benchmarks/`，不使用机器相关时间作为正确性断言。

## 完成顺序

```text
阶段 1：可信原始公理环境
    ↓
阶段 2 第一版：严格正普通归纳类型（非索引）
    ↓
阶段 2 第二版：索引归纳
    ↓
阶段 3：点和一阶路径 HIT
    ↓
阶段 4 第一里程碑：二维高阶路径与规则安全
    ↓
阶段 4 第二里程碑：三维高阶路径与完整沙盒管理
    ↓
阶段 4 实验边界：四维 fixture、预检拒绝和资源限制
```

任何阶段都不得通过放宽内核检查来提前模拟下一阶段。阶段 1 可以允许用户承担公理一致性责任，但阶段 2 至阶段 4 生成的归纳器和计算规则必须由系统验证并明确区分定义相等与命题相等。阶段 4 的二维和三维能力必须逐维完成独立认证；四维及以上必须明确报告为不支持，不能作为任意维能力对外承诺。
